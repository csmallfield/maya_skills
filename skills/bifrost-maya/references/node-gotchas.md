# Node gotchas and proven idioms (Bifrost 3.0)

Verified while building CityGen (bifrost_citygen repo) on 2026-10-29 with verify_compound.py and live Maya.

## Type inference
- `Geometry::Strands::resample_strands` won't compile unless its `auto` ports are typed: "The data type could not be inferred for one or more input ports of ...: distance_per_strand, minimum_resample_distance". Give `distance_per_strand` an `array<float>` literal `[]` and `minimum_resample_distance` a float literal.
- `Geometry::Properties::get_geo_property` needs its `type` port given as a literal of the wanted array type, for example `array<float>` `["0f"]` or `array<uint>` `["0U"]` (that one reads `strand_offset`).
- `Core::Logic::not` only has vector-bool overloads (bool2 and up). To invert an `array<bool>`, use `Core::Logic::equal(x, false)`.
- `Core::Logic::if` needs both branches to have the same type. To pick per element between an array and a constant, first broadcast the constant into an array, for example `add(multiply(positions, 0), constant)`.
- `Core::Math::max` outputs `maximum` (and `min` outputs `minimum`), not `output`, while `add`, `subtract`, `multiply` and `divide` output `output`.

## Graph shape and cost
- **Don't feed a value into both branches of a chained `if`.** `keep = if(condition=keep, true_case=test, false_case=keep)`, repeated once per test, uses each step's `keep` twice. At 7 steps that was harmless. At 24 steps the stage took **about 120 s** whatever the data size (13k and 164k elements both took that long), so the cost was fixed, not tied to the data. Its size points to the graph being expanded as a tree, about 2^steps. Write each step so the running value is used once: `keep = if(condition=test, true_case=keep, false_case=all_false)`, with `all_false` an `array<bool>` built once (`less(length(any_matching_array), 0)`). Same results in 1.3 s (CityGen v018, 2026-10-30). There is no array `and` (`Core::Logic::and` is bool2 to bool4 only). Suspect this whenever a stage's time stays constant as the data changes size.

## Idioms
- **Is anything within r?** `Geometry::Query::get_closest_point(geometry, positions, use_cutoff_distance=true, cutoff_distance=r).found` gives one bool per query position, vectorised. Use it in place of an O(n×m) loop.
- **Boolean cutters from many segments:** instance a unit `create_mesh_cube` on points carrying `point_orientation` and `point_scale` (`create_instances`), bake them with `Modeling::Instances::bake_instanced_geometry.merged_meshes`, and wire `[slab, cutters]` into `boolean_meshes.meshes` (fan-in, operation `Subtraction`). Proven on a 400 m slab minus 355 overlapping boxes: 24 islands in a few seconds. The output is **triangulated** (about 19k triangles here). Count islands with `Geometry::Mesh::find_mesh_islands.face_island_count`.
- **Consecutive point pairs within strands:** take `strand_offset[1:] - 1` as the sorted last-point indices, then `find_in_sorted_array(value = all point indices).found` marks each strand's last point. Filter it out to get segment start indices.
- **Yaw from a direction:** `axis_angle_to_quaternion(axis (0,1,0), radians = atan_2D(y, x))`. To map +X onto (dx, dz), use `atan_2D(-dz, dx)`. To map +Z onto (dx, dz), use `atan_2D(dx, dz)`.
- **Concatenate arrays:** `flatten_nested_array(build_array(a, b))`.
- **Per-element constant property:** `multiply(length(unit_vectors), value)` gives an array of `value` matching another array's length.
- **Snap to the nearest vertex:** `get_closest_point(...).point_indices` feeds `get_from_array(point_position, ...)` to get the matching vertex positions (`locations` is a sampling handle for `sample_property`, not positions). Mask the result with `.found`.
- **Greedy non-overlap of equal rectangles:** an iterate loop over candidates keeps the accepted centres and fronts as state. Run a 2D separating-axis test of the new rectangle against all kept ones at once (four axes, with `absolute_value(dot(...))` projections), reduce with `any_true_in_array`, and append with `flatten_nested_array(build_array(kept, build_array(new)))`. In CityGen it took overlapping building pairs from 49 to 0 on 138 candidates in about 1 s. Check results outside Bifrost too: `bifrost_citygen/tests/check_overlaps.py` re-runs the SAT on an exported .usda.

- **Exact grid bucketing inside a sequential greedy loop:** when items can only interact within a distance R, use cells at least R wide and test only the 3 x 3 cells around each candidate. The result is the same as testing everything. Keep the kept items as `array<array<T>>` loop states, one per field, plus each item's acceptance index:
  - **Before the loop:** compute each candidate's cell index (`round_to_floor`, `to_long`, with a 1-cell border so neighbours never fall off) and the 9 neighbour offsets.
  - **Each iteration:** `get_from_array(nested, cell + offsets)` gives the 9 cells; `flatten_nested_array` gives the local kept items. On accept, `set_in_array(nested, cell, concat(own_cell, [new]))`.
  - **After the loop:** flatten, then `sort_array_with_indices` on the acceptance index to restore the original order.

  In CityGen v019 (SAT on 164k candidates at 2000 m) this cut the loop from 3.3 s to 1.3 s, and from 14.9 s to 1.9 s at 3000 m, with an identical result. Below about 200 kept items it is slightly slower than testing them all.

  **Keep only indices in the cells.** One `array<array<long>>` of kept candidate indices, with the fields read back by `get_from_array(field_array, gathered_ids)`, halved the loop again: 1.3 s to 0.6 s at 2000 m (v020). Six nested field states cost more per iteration than the SAT they feed. If candidates are tried in index order, sorting the kept indices also gives the acceptance order.
- **Seeding an `array<array<T>>`:** `build_array(empty array<T>)` resolves to `array<T>`, and the following `resize_array` fails with "no common type promotion exists between 'Math::float3' and 'array<Math::float3>'". Use an `array<array<T>>` value node holding `[]` as `resize_array.array`, with the empty `array<T>` as `default` and the cell count as `new_size`.

## Vectorised graph algorithms (verified 2026-10-30, CityGen v022: planar road graph -> faces)
Bifrost has no maps or pointer-chasing loops that are cheap, but sorting, `prefix_sum` and `get_from_array` with index arrays cover most graph work:
- **Unique ids from keys:** `sort_array_with_indices(keys)`; first-of-run flags (`sorted != sorted[i-1]`, or i == 0); `prefix_sum(flags, Inclusive, output_type array<long>) - 1` gives the run id per sorted slot. To map back to the original order, use the inverse permutation, which is `sort_array_with_indices(sorted_indices).sorted_indices` (the argsort of a permutation). To merge points, quantise positions into one long key, `(round(x / eps) + shift) * row + (round(z / eps) + shift)`. Two points closer than eps can still round to different keys, so clean up afterwards (drop near-duplicate neighbours).
- **Per-group first and last slot** in a sorted key array: `find_in_sorted_array(sorted, value).found_index` gives the first slot. For the last, sort the negated keys and search for the negated value: last = n - 1 - that index.
- **Cycle labels:** pointer jumping in an iterate loop, `label = min(label, label[next]); next = next[next]`. ceil(log2(longest cycle)) rounds give every element its cycle's smallest index. **List ranking** works the same way: break each cycle at its leader (`succ = self`), then `steps += steps[succ]; succ = succ[succ]`.
- **Segmented sums:** an inclusive `prefix_sum` over the group-sorted values, then `cum[last] - cum[first] + value[first]` per group.
- **Planar faces:** half-edges sorted by `origin * 8 + (atan2 + 3.2)`; next(a->b) is the half-edge before b->a in that order (wrapping at the group's first slot). Segment crossings must be tested **inclusively**: grid-aligned input puts vertices exactly on other segments, and a strict sign test misses them. Compute each crossing point identically from both segments (the lower index's parameter, or the touching end point itself) so the two copies merge.
- `prefix_sum` won't produce `array<uint>` from `array<long>` ("can't pass a value of type 'array<long>'"); convert with `Core::Type_Conversion::to_unsigned_int` (port `.unsigned_int`; there is no `to_uint`). `uint` input can produce `uint` offsets (`PrefixSumStyle` `OffsetArray`) for `construct_strands`.
- `USD::Prim::define_usd_curves` does not export custom point properties (an `edge_half_width` float per point was dropped).

## Comparing exported USD
- `export_stage_to_file` writes `.usda` text. Instancer arrays (`positions`, `orientations` as `quath` real first, `scales`, `protoIndices`) can be parsed with stdlib regex for independent checks, without pxr.

## USD pack (verified 2026-10-29, CityGen v007)
- **Instancing referenced assets:** for each asset, `define_usd_reference_from_file(file)` feeds `define_usd_prim(path="/<name>", reference_definitions=[ref])`. Pass those prim definitions to `define_usd_point_instancer.prototype_definitions`, with `instance_id_override` = per-point asset index (the points carry no `point_instance_id`). The prototypes land under `<instancer>/prototypes/<name>`.
- **The prototypes relationship comes out reversed:** definitions [a, b, c] are written as targets [c, b, a], and `protoIndices` index the targets. Feed the definitions through `reverse_array` so that index k is asset k. Check with pxr: `PointInstancer.GetPrototypesRel().GetTargets()`.
- **Prototype paths need a leading `/`.** A bare `name` produced targets like `/City/Buildings/prototypesname`.
- **`export_stage_to_file` flattens.** References are resolved and their content is copied in. To keep the composition arcs, export `USD::Layer::get_root_layer(stage)` with `export_layer_to_file` (`relative_path=false` keeps absolute asset paths).
- **`create_usd_stage.file_format` defaults to `Binary`**, whatever the file extension. Set it to `ASCII` (the UI values are `Binary` and `ASCII`) for text you can grep.
- **Viewing the result:** a `mayaUsdProxyShape` with `.filePath` shows the assets' proxy purpose by default. Set `drawRenderPurpose 1` and `drawProxyPurpose 0` to see render geometry.
- **`export_layer_to_file(relative_path=true)` does not relativise references**, only sublayers. Asset paths stay absolute. Rewrite them afterwards with pxr `UsdUtils.ModifyAssetPaths(layer, fn)` in live Maya (`bifrost_citygen/tools/relativize_usd.py`). When checking that prototypes compose, remember that referenced assets can hold their own PointInstancers, whose prototypes are leaf gprims with no children.
- **Point-probe clearance tests miss roads that end between the probes.** Testing a rectangle by a few probes (centre, corners, inset ends), each with "nearest road point minus that road's half width >= margin", leaves the middle of each long edge unguarded. A dead-end road pointing at that edge midpoint is far from every probe while its surface reaches the footprint, especially when the road surface (or its boolean cutter, often a box extended by half a width past each segment end) runs past the last centreline point. A road with half width h, missed by probes spaced s apart along an edge with margin m, can reach the edge whenever s/2 > sqrt(2*h*m + m^2): 2.5 m for h = 6 and m = 0.5. In CityGen v017 at 2000 m, two skyscrapers were clipped 2 m and 4.9 m deep by 20 m arterial dead ends. The fix that worked (v018): a fixed number of probes on every edge (9 on long edges, 5 on short ones). With probes s apart, require distance >= sqrt(h^2 + q^2), q = max(s/2, 2.5 m). That catches any road within h of the edge, and still passes a lot facing its own road at h + 2 m setback while s <= 8 m.
- **Closest-point queries inside a loop: build the accelerator once.** `get_closest_point` rebuilds its search structure on every call. Inside an iterate loop over a large, unchanging geometry, build it once outside with `Geometry::Query::build_closest_accelerator(geo, geo_component "point_component")`, pass the `accelerator` Object in, and query with `sample_closest_point_accelerator(accelerator, position, use_cutoff_distance, cutoff_distance)`; its outputs are `point_index` and `found`, not `point_indices`. For strands, the default component (an empty string) is `strand_component`, so name `point_component` to get vertex indices. CityGen v021: 120 march steps against 60k road points took 0.9 s per call this way, down to 0.36 s. Querying only the points that matter (filter, then put the results back with `find_in_sorted_array(...).found_index`) saved another 0.3 s.
- **Excluding a point's own neighbourhood from a closest-point test:** to ask "is this strand end on *another* road", query a copy of the roads with each strand's first and last few points removed (`Modeling::Strands::delete_strands_points`, indices from `strand_offset`). Otherwise the end always finds itself at distance 0.
- **Vertex-based distance tests miss long segments.** `get_closest_point` finds the nearest *vertex*, so a polyline with a long straight segment (for example a road end moved by snapping) is invisible along its length. Resample the strands (`resample_strands`, every 2 m) before querying distances.

## Booleans (measured 2026-10-29, CityGen v010)
- `boolean_meshes` time grows with the number of cutter boxes, not with the slab. Halving the boxes (road segments every 36 m instead of 18 m) cut a 1200 m city's block boolean from 10.0 s to 3.3 s with identical islands.
- `fix_self_intersections=false` with overlapping cutters baked into one mesh returns an **empty** mesh. Leave it on whenever the cutters overlap each other.
- For a fast approximate region split, rasterise instead: a `create_mesh_plane` grid, `get_closest_point(...).found` on the face centres (with a cutoff), then `delete_faces(faces_to_delete = that array<bool>)`. This took 0.43 s against 3.3 s at 1200 m, but the edges are stepped at the cell size and small regions can vanish.

## Numbers and literals (2026-10-29, CityGen v011)
- **`to_long` / `to_int` truncate.** `to_long(length(unit_vector))` is often 0, because the length comes out as 0.99999. Use `round_to_nearest` before converting whenever the value should be a whole number. In CityGen this silently relabelled some lots as asset 0 for four versions.
- **Bool values through `cmds.vnnNode(..., setPortDefaultValues=(port, value))`: use `"1"` / `"0"`.** `"true"` was accepted without error but left the port false (seen on `ppg_urban_multistyle_v4_3.usd_write`). In native JSON, the literal `"true"` is fine.
- **Pulling a `BifrostUsd::Stage` output headless:** `bifrost_headless.py` can't read a Stage output. To force a compound's stage (and its export) to evaluate, wire it through `USD::Layer::get_root_layer` and then `get_layer_identifier`, and read that string output.
- **Payload prototypes:** `define_usd_reference_from_file(arc_type = BifrostUsd::ArcType Payload)` writes `prepend payload = @file@</prim>`. Check deferral with pxr: `Usd.Stage.Open(path, Usd.Stage.LoadNone)` should list the instancer and its instances, but leave its prototype prims unloaded (`prim.IsLoaded()` false).
- **Stage metadata from Bifrost:** chain `USD::Stage::set_stage_metadata(key "defaultPrim", value string)`, `set_stage_metadata(key "metersPerUnit", value double)` and `set_stage_up_axis(axis Y)` after `add_to_stage` and before `get_root_layer` and `export_layer_to_file`. To give the root prim a kind, add an explicit `define_usd_prim(path "/City", type "Xform", kind Assembly)` first in the `add_to_stage` fan-in; prims defined below it merge under it.
- **Timing a stage open inside a live Maya** tells you little once the layers are cached in the session; time it in a fresh process.

## USD variants (verified 2026-10-29, CityGen v015)
- **Author variant content with `USD::VariantSet::add_to_stage_in_variant`** on the stage: `parent_path` is the prim that gets the variant set, plus `variant_set_name`, `variant_name`, `select` (bool), and the `prim_definitions` to place inside the variant. Child paths like `/Render` land under `parent_path`. Call it once per variant, with stage as an iterate-loop state when many prims need variants.
- **Prim-definition children with `variant_set_name` / `variant_name` set do not create variants.** `define_usd_prim(variant_set_definitions=[define_usd_variant_set(...)], children=[...])` wrote the children as plain overs, outside any variant, and wrote no variant set at all.
- **An over that only deactivates:** `define_usd_prim(path, type "", specifier Over, active False)`. `purpose = Default` authors nothing (it's the fallback value), so use `Render` to make a proxy drawable by renderers.
- **Don't edit stages you open for testing inside a live Maya.** `Usd.Stage.Open(path)` there reuses the session's cached layer, so `SetVariantSelection` and similar calls dirty the layer MayaUSD will show next. Undo with `Sdf.Layer.Find(path).Reload(force=True)`, while no proxy shape composes that layer.
